# Debug Specification

## Purpose

debug 基于已知预期与实际行为偏差建立因果证据，可独立诊断，也可为仍持有修复授权的 implement 提供支持。

## Requirements

### Requirement: 诊断以预期偏差和本地证据为基础

debug 必须区分预期、实际及触发条件，在修改前核对用户报告、项目契约、源码、类型和适用的文档或变更记录，不得把常见症状直接当作本地根因。可发现事实由 Agent 调查，预期行为仍涉及未定产品语义时由 shape 澄清，同时继续不依赖该选择的调查。复用有效项目事实，不新增固定 Explore 前置流程。
Verify: manual(integration)

### Requirement: 反馈信号与可证伪假设驱动调查

debug 必须寻找可区分故障与正常行为的反馈信号，尽可能重现原始条件并缩小触发范围，基于证据提出可证伪假设，选择能够区分解释的观察或实验。实验前明确哪些结果支持或反驳假设，获得反证后更新判断，不堆叠猜测性修复。观察环境不可用不证明目标系统存在某种故障；不存在固定假设数量、耗时门槛或无法稳定复现就停止所有调查的规则。
Verify: manual(integration)

### Requirement: 诊断结果区分因果证据与未知

debug 必须报告已建立的因果判断及区分其他解释的实际证据，或明确当前只能支持的结论、剩余假设和具体证据缺口；不得虚构复现、把直觉当根因或把症状变化当作修复证明。交给修复的回归场景必须能暴露原故障，修复后既要检查诊断信号，也要重放原始触发路径；缩小后的局部通过不能替代原行为结果。
Verify: manual(integration)

### Requirement: 诊断支持调用不扩大修复授权

debug 只使用当前任务已有权限开展探针和实验，不因诊断调用获得持久源码、测试、依赖或外部状态的修改权；清理自身临时探针时保留其他工作和有授权的回归覆盖。独立诊断可以原因、证据或明确未知结束；在已授权修复中必须把结果返回 implement，由 implement 负责代码、回归测试、直接受影响文档及最终行为，继续验证或调查，不强制切换 Agent，不因诊断结束而要求重复授权同一修复。
Verify: manual(integration)
