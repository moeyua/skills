# Gold cases:judge 校准基准

两个人工判卷过的真实 codex shape 会话(2026-07-02,用户人工判卷 + 三个评估员会话交叉验证),
用于校准 LLM judge 的判定方向与总分刻度。校准目标:逐项判定方向一致、总分差 ≤1。

## 案例结构

每个 `case-*/` 目录:

- `manual.json` — 人工判卷基准:总分、逐条 spec Requirement 的人工判定(`pass` / `fail` / `partial` / `n.a.`)、来源与备注。`partial` 表示人工认为部分满足,比对时与 judge 的 pass 或 fail 都视为方向一致。
- `transcript.json`(仅案例 2)— 手工构造的 normalized transcript。案例 2 只有截图转写,没有完整 rollout JSONL,人工也是在这个信息量上判的卷,judge 用同样的输入才公平。

## 运行校准

```bash
node bench/src/calibrate.ts            # 每案例判 1 次
node bench/src/calibrate.ts --repeat 3 # 判 3 次,量化 judge 抖动
```

冲突项或总分差 >1 时 exit 非 0。

## 校准结果(2026-07-02,rubric 修订后,--repeat 3)

| 案例                 | 人工分 | judge 三次判分 | 分差最大 | 抖动 | 逐项方向   |
| -------------------- | ------ | -------------- | -------- | ---- | ---------- |
| case-1-tapnow-qrcode | 8      | 8 / 8 / 8      | 0        | 0    | 30/30 一致 |
| case-2-skland-token  | 6      | 6 / 5.5 / 5.5  | 0.5      | 0.5  | 30/30 一致 |

解读矩阵时的噪声参考:单会话判分抖动约 ±0.5,分差 ≤0.5 不构成回归信号。
