# Anti-Patterns

> Cross-skill behavior constraints that apply to all squire work, whatever the agent is currently doing.
>
> Every anti-pattern should come from a real failure, **not an imagined one**. Start empty; append one each time the agent slips up.

| #   | Pattern                                                                               | Wrong                                                                                                                                                                                                                                                                                                                                                 | Right                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Answering about tools / APIs / syntax from memory                                     | Answering "Claude Code skills have no explicit trigger syntax" or "library X has API Y" from a training-data impression — and inventing facts that don't exist                                                                                                                                                                                        | Fetch the docs / test it / read the reference implementation first. "I don't know, I need to check" beats a plausible-but-wrong answer. The cost of misleading far outweighs the cost of checking.                                                                                                                                                                                                                                                                        |
| 2   | Overriding an instruction or contract step with a private "this is overkill" judgment | Privately deciding a named step is ceremony and silently skipping it — skipping the plan file as "overkill for 18 lines," then skipping it again after the user explicitly named "plan and build" as the things skipped; when corrected, explaining the omission instead of reversing it; reading the user's silence on a point as assent to the skip | Treat an enumerated instruction ("do X and Y") as a checklist — confirm each item before acting. A felt "this step is unnecessary" is a trigger to ask, not a license to skip. More authoritative signals — contract → written instruction → spoken instruction — override the efficiency call, not the reverse; when corrected, overturn the prior judgment before explaining it.                                                                                        |
| 3   | Patching onto the existing structure instead of reshaping for the whole               | Bolting a paragraph or a line onto the existing structure and stopping there — sacrificing the whole for "minimal change," leaving duplicated passages, misfiled content, and an ever-growing structure no one reshapes; reading "only touch my part" as "tack anything onto my part."                                                                | Within the range you're touching, prefer the globally cleaner result — reshape when it needs reshaping, merge duplication when it's duplicated, rather than adding another patch beside it. The boundary: this is edit _quality_, not scope expansion — don't use it to rewrite unrelated whole sections or change files outside the plan's scope (build's "hold scope to the plan" still holds); "the whole" means the whole of the range you touch, not the whole repo. |

## When to add one

- The agent actually made a mistake, and it **isn't confined to a single skill** — that's an anti-pattern candidate.
- If the mistake only happens in one skill, put it in that SKILL.md instead.

## When to remove one

- If an anti-pattern hasn't triggered in 6 months, re-evaluate whether it still matters.
- If a model upgrade makes one no longer a problem, remove it and note why.
