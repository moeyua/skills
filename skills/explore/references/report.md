# Explore Report Interface

Load this reference only when project or module understanding is the user-facing deliverable.

Adapt the detail to the question while preserving this interface:

```markdown
# Explore Report: <project or scope>

## Project identity

- positioning and source
- language, framework, and key tooling
- run and verification commands with their source

## Structure

- top-level responsibilities
- key modules and entry points

## Documentation inventory

- global documents actually read and a one-line summary of each
- relevant scoped documents and their claims

## Scoped deep-dive: <scope>

<include only when a scope was named; organize with deep-dive.md>

## Uncertainty

<only facts that could not be established or source conflicts that matter>
```

The report is the outcome, not a launchpad for a workflow. Do not append generic next-step recommendations or list documents that were merely discovered but not read.
